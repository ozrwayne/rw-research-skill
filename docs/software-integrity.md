# 软件完整性检查

## 确定性检查

```sh
python3 -m pip install -r ci/requirements-test.txt
python3 scripts/run_ci_manifest.py
```

`ci/manifest.json` 仍是共同检查入口。测试收集包含仓库 `tests/`、每个 Skill 的 `tests/test*.py` 与 `scripts/test_*.py`。缺依赖和空测试集失败，不以跳过代替通过。PDF 测试使用固定版本的 PyMuPDF 和 Pillow。检查、单元测试和构建不发起模型请求。

跨模型 `check` 只检查本地定义；不执行 `run` 或 `preflight`。完整矩阵状态需要模型、任务、两种条件和重复次数都齐全且运行结束。部分记录和重复记录不获得完整验证标记。响应须符合仓库使用的有限 JSON Schema 词汇，再接受逐字段评分；不支持的 Schema 关键词失败。

## 同步

同步前检查 manifest 名称、所有选中源文件和目标目录。复制和公开内容处理在临时目录完成后，再切换目标目录。失败时保留旧目录；发布第二次 rename 失败时恢复备份。

- `--only` 只更新明确选择的 Skill。
- 默认不删除 manifest 外目录；只有显式 `--prune` 才删除它们。
- `--dry-run` 也校验复制和公开内容处理，但不替换原目标。
- 源案例的合成声明是人工核实的前提，不由同步脚本凭空生成。
- 包名、版本、Skill 名称不接受路径片段；复制和打包拒绝符号链接及非普通文件。

这不是断电事务：两次目录 rename 之间进程终止可能留下 `.previous-*` 备份，需要人工恢复。没有跨进程锁；检查期间不应并发修改包输入。无需把这些实现限制写成“已证明原子性”。

## 构建

ZIP 先写临时文件，完成后替换旧 ZIP。SkillHub 先完成仓库校验、生成、实际生成物隐私检查和 ZIP 构建，再替换旧目录。目录与 ZIP 的替换不是跨文件事务。

SkillHub 的命令以包根目录执行。模块在 `modules/`，运行工具在 `tools/<Skill>/`，模板在 `templates/<Skill>/`；参考资料合并为模块中的显式锚点。完整仓库的测试与 self-check 不随精简包分发，不在生成物中声称这些命令可直接运行。

## 证据边界

结构、路径、隐私模式、Schema 和确定性测试通过，不证明所有模型都遵循行为合同，也不证明科研结论正确。历史跨模型运行保留原记录；本次软件检查没有重新执行这些模型。
