# 内容取舍与位置检查

## 使用时点

在零稿、续写、修改、导师反馈和多轮优化中，先判断当前需要什么内容，再检查表达。判断范围包括句子、段落、小节和章节；实际修改仍限于作者批准的范围。本规则是包内实践方法，不声称是经验证的学术标准。

## 写前取舍

依据研究问题、目标读者、已提供材料和报告责任，确定：
- 此处必须说明什么，为什么需要在此处说明。
- 上文已充分建立什么，无需再解释什么。
- 哪些内容属于后文、其他章节或补充材料；指定位置而非到处重复。
- 哪些内容无关或没有必要；不因有来源、真实或容易写就加入。
- 哪些必要内容仍缺证据或作者决定；缺口留在工作记录，不用通用意义句填充正文。

先确定内容和位置，再写论点与证据骨架。对研究设计决定，区分作者已确认／方案已规定、暂定、助手建议和来源不明；草稿出现过不等于作者批准。不要反复替尚未确认的决定辩护。

这些判断按任务规模在内部完成。短段落不强制输出规划表，每段也不必显式写出研究问题连接、重要性和局限。

## 两个判断维度

必要性与完整性分开。清楚、准确、有引文不等于值得保留；重要但证据不足也不等于可以悄悄删掉研究义务。

| 字段 | 值及用途 |
|---|---|
| `necessity` | `needed`、`redundant`、`misplaced`、`unnecessary`、`undetermined` |
| `completeness` | `complete`、`needs_evidence`、`needs_explanation`、`needs_link`、`needs_author_decision`；可多选 |
| `action` | `KEEP`、`DELETE`、`MERGE`、`MOVE`、`REWRITE`、`NEEDS_EVIDENCE`、`AUTHOR_DECISION` |
| `reason` | 删除会失去什么，或内容已由何处承担；“有过渡作用”本身不是充分理由 |
| `destination` | 仅 MOVE 或 MERGE 时记录具体位置和权限状态 |
| `argument_status` | `complete` 或 `unresolved`；删除无据主张不自动补全论证 |

动作只表述内容建议，不等于批准执行。选择 DELETE 时可以不写替代句；KEEP 可以零改动。MOVE 保留义务并检查新位置，不把尚未执行的移位记为完成。NEEDS_EVIDENCE 和 AUTHOR_DECISION 区分事实缺口与决策缺口。旧版段落 `status` 继续描述完整性，不替代 `necessity`。

## 删除与保留的实质检查

暂时拿走候选内容，重读相邻论证，必要时检查同章或跨章对应位置：
1. 是否丢失当前必需的事实、定义、比较、理由或真正的逻辑连接？是否产生悬空指代？
2. 是否改变主张范围、确定性、因果／否定强度，或隐去影响结论的反证？
3. 是否损害报告透明度、复现、方案偏离说明、测量或分析解释？读者仍看得懂并不足以证明可以删除。
4. 相同作用是否已由其他内容充分完成？说明位置。摘要、章节回顾和跨章导航允许有必要的重复，不用机械去重。
5. 是否只是位置错误？在获准范围内移位；范围外保留为建议。

删除多余内容后，检查论证是否仍完整。删除无依据的唯一研究理由后，分别记录“无据句已移除”和“研究理由仍未建立”，不标整段通过，不补上空泛的“仍需进一步研究”。

不以新事实数量判断句子价值。必要的定义、估计目标、科学限定、反证、报告细节和导航可以保留；不按 `not`、`but`、否定、抽象程度、句长或 AI 分数裁决。作者讨厌保守表述可以影响措辞，不能改变相同证据下应有的不确定性。

## 生成后与反馈后的顺序

1. 检查必需内容有无遗漏、重复、错位和未决问题，再处理保留内容的证据与解释缺口。
2. 对确实需要保留但含糊的内容，运行概念闭合及读者推断检查；对照句专项判断见 `references/abstract-contrast-gate.md`。
3. 最后校准表达和语气，并核对原意、主张强度、引文支持及获准范围。

“Reword”“Expand”“AI-like”是问题线索，不预先指定 REWRITE 或扩写。禁止为了响应批注而给无必要的整段补一个 key message。多轮“继续优化”先检查前一轮是否多加了内容，必要时撤回；删除后不在相邻句或后续轮次用同义过渡重新塞回相同内容。出现新证据或读者需求时可以重新评估，说明理由。

## 验收与证据

分别验证：冗余是否处理、无据主张是否处理、论证是否完成。补丁成功、引用全对、文字流畅均不单独证明第三项。保留必要内容和零修改同样是正确结果；不设删除比例或字数缩减目标。

合成回归输入与期待行为保存在 `references/behavior-tests.json`，`gate = content_necessity_v1`。给执行者的输入不得包含答案字段；保留输出和 Skill 版本，记录误删、遗漏、主张漂移、冗余回流和未解决论证。静态合同检查只验证结构，同一执行者演练不算独立验证。旧新版比较使用相同材料和模型、隔离上下文；没有实际旧版输出不报告提升率。
