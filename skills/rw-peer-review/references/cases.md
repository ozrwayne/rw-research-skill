# 案例和反例

> 公开案例使用合成或占位输入，不来自任何个人研究项目。

## 案例 1：数字对不上

- 稿件正文写“提升 15%”，表 2 的两个数字算出来是 12.8%。
- 意见带位置、原文、问题和改法，`publication_impact` 记 `blocking`。
- 作者补出换算过程后转 `withdrawn`，并连上那份来源。

## 案例 2：说的比证的宽

- 标题写“持续优于现有方法”，正文只测了两个数据集。
- 意见写出数据实际支持的最窄说法，和标题并排比。
- 作者收窄标题后转 `answered`，写明改到哪一句。

## 案例 3：辩论后收窄

- 唱反调指控核心定理没有证明。
- 作者指出附录 B 有证明，但只覆盖有界情形。
- 意见转 `narrowed`，说明收窄到无界情形仍未证明。

## 反例：口头认输

- 作者反驳得很诚恳，但没有给出新的材料或位置。
- 不能转 `withdrawn`，只能是 `sustained` 或 `narrowed`。

## 反例：综合环节补意见

- 综合环节读稿时自己发现一个新问题，直接写进编辑判断信。
- 这条判断追不到任何已登记意见，不允许写入，退回对应 Agent 登记。

## 案例 4：回应提到了，但正文还没补

- 作者回复指向补充表，补充表支持回应的一部分。
- `response_mentioned=yes`，`response_hits_issue=partial`，`response_is_sufficient=partial`。
- 正文没有报告读者复核所需的方法和诊断，`body_still_needs_reporting=yes`。
- Finding 转 `narrowed`，不转 `answered` 或 `withdrawn`。

## 案例 5：两个 p 值都没过阈值

- 主分析 `p=.067`，敏感性分析 `p=.052`，两者都没过预设阈值。
- 分别记录估计值、区间、方向和目标效应是否一致。
- 不写“接近显著”“结果受影响”或“敏感性分析证明稳健”。

## 反例：多 Agent 一致等于结论可靠

- 3 个 Agent 从同一稿件和同一表格提出相同问题。
- 这说明问题能被重复发现，不说明结论被独立数据或不同方法验证。

## 反例：内部学习记录进入审稿信

- 编辑判断信写入用户初判、模型名称、Agent 辩论和迁移结果。
- 干净度检查失败，退回清理后再交付。

## 案例 6：第一次审稿

- 用户说自己从未审过稿，不能说明一条结论由哪项结果支持。
- 系统进入 `guided`，先给合成基线题，再给不同主题的 worked example。
- 用户之后填写当前 Finding 的引导审稿卡，机器只反馈漏证据、推断越界、严重程度和修改可执行性。

## 案例 7：报告完成但还没掌握

- 用户在机器引导下完成一份可交付报告。
- 7 项质量维度中有 2 项仍为 `needs_work`，独立案例没有达到预设标准。
- `ready` 可以 PASS，`mastery` 保持 REVIEW。

## 反例：用当前稿件做 worked example

- 机器先把当前 Finding 的标准判断完整展示，再要求用户写初判。
- 用户只是在复述答案，不能作为初判或迁移证据。

## 反例：一次通过后关闭脚手架

- 用户第一次完成观察性研究审稿后，系统直接让其独立判断非线性交互模型。
- 问题类型变化，应回到 `guided`，不能沿用上一类任务的掌握状态。

## 案例 8：按外部标准评定

- 导师在练习前声明使用 RQI 核心维度，并要求完成其课程规定数量的独立同类案例。
- 每个案例保存完整评审、问题检出、质量维度和导师反馈。
- 达到标准后由导师记录 `meets_predeclared_standard`，`mastery` 才可 PASS。

## 反例：承诺 30 分钟掌握

- 系统把第一次引导写成“30 分钟掌握审稿”。
- 短期训练研究不支持该承诺，应改为“完成第一次结构化练习”，并单独记录后续表现。

## 反例：报告清单代替批判性评价

- CONSORT 条目都能找到，系统直接判定随机试验方法可靠。
- 清单只说明报告信息较完整，仍需核对随机化、偏倚、分析和结论解释。

## 案例 9：表格脚注改变分母

- Table 2 主体写 `12/100`，脚注说明 2 人因缺失结局被排除，Results 使用 `12/98`。
- 表格凭据把 caption、footnote、Results 段落、分析人群定义和 Supplement 表设为必要依赖。
- 当前 Finding 的 Context Pack 只包含这些凭据及相邻文字，不发送全文的其他数百张凭据。

## 反例：为满足 token 上限删除脚注

- 必要依赖闭包超过设置上限，系统只保留表格图片和 Results 段落。
- 这会制造不完整上下文。正确结果是 BLOCK，并拆分 Finding 或调整明确的工程上限。

## 反例：Supplement 更新后复用旧判断

- 作者提交新版 Supplement，旧 Context Pack 的来源 hash 已变化。
- 原包和相关 Finding 转为 `stale`，重新提取和验证后才能进入综合。
