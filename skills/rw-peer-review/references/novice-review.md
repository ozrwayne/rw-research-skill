# 零经验审稿引导

目标是帮助用户写出可定位、有依据、与稿件范围相称的评审意见。Skill 不承诺短时训练会让用户成为合格审稿人，也不把一次报告完成当作掌握。

方法和证据边界见 `references/novice-review-sources.md`。

## 入口判断

用户第一次审稿、说自己没有经验，或不能说明“结论—证据—问题—影响”时，使用 `mode=guided`。

开始前先核对：

1. 期刊的 reviewer instructions 和评审模式。
2. 用户能审哪些部分，哪些部分超出其专业范围。
3. 利益冲突、保密和是否允许导师或其他人参与。
4. 正文、补充材料、报告清单和期刊要求是否齐全。

专业范围不足或材料不全时，先向编辑说明，不让教学流程掩盖边界。

## 第一次引导

### 第 1 步：合成基线题

给一份带预设问题的合成短稿。用户先提交评审，不提前看答案。记录两类结果：

- 报告质量：是否讨论研究问题、原创性、方法、报告、结果解释，意见是否建设性并有依据。
- 问题检出：预设的重大问题识别了哪些、漏了哪些。

基线只用于选择后续练习，不作为能力标签。

### 第 2 步：不同案例的 worked example

换一份合成材料，展示：

1. 确认研究问题、研究类型和报告指南。
2. 定位作者最强结论和支持它的结果。
3. 区分报告缺失、方法问题和解释越界。
4. 判断该问题对结论和编辑决定的影响。
5. 写出有依据、可执行、不过度扩展研究范围的意见。

worked example 不使用用户当前稿件，避免用户复述答案。

### 第 3 步：当前稿件引导卡

用户针对当前 Finding 填写：结论、证据位置、研究设计、研究对象、estimand 或目标效应、问题类型、录用影响、建议修改，以及什么证据会改变判断。

### 第 4 步：对照反馈

反馈同时使用 3 类依据：

- 期刊要求和适用的报告指南。
- Review Quality Instrument 的核心维度。
- 合成案例预设的重大问题或导师／编辑确认的评审标准。

机器指出漏掉的证据、推断越界、严重程度不匹配和无法执行的建议。用户自己重写终判。

### 第 5 步：独立案例

用户在不看示范答案的情况下评审另一份同类材料。保存完整评审、标准、评定人和反馈。重复次数由预先声明的课程、期刊或导师标准决定。

## 评审质量维度

基于 Review Quality Instrument 的核心维度记录：

- 研究问题的重要性。
- 原创性。
- 方法的优点和缺点。
- 表达与报告完整性。
- 结果解释。
- 意见是否建设性。
- 意见是否有证据支撑。

同时检查 COPE 边界：专业范围、利益冲突、保密、评论与建议是否一致、额外工作是否确实为支持当前主张所必需。

## 掌握判断

专业文献没有提供“训练多少分钟”或“连续通过几个案例”即可掌握同行评审的通用阈值。短期培训对评审质量的平均改善有限，长期保持也不确定。

因此 `mastery` 只在以下条件同时满足时返回 PASS：

1. 已预先记录课程、期刊或导师采用的评定标准和来源。
2. 已完成该标准要求数量的独立同类案例。
3. 7 项质量维度均达到该标准。
4. 没有漏掉会改变主结论或编辑建议的重大问题。
5. 评定人明确记录 `meets_predeclared_standard`。

该 PASS 只适用于记录中的研究类型和问题类型。新的设计、统计模型或测量问题需要重新评定。

## 最低交付标准

- 每条意见能定位到原文或数据。
- 说明证据为什么不足，不只报结论。
- 区分报告问题、方法问题和解释问题。
- 严重程度与结论影响相称。
- 修改建议可以执行，且不把扩展研究范围当成必要修改。
- 材料不足时写 `not_verified`，不猜。
