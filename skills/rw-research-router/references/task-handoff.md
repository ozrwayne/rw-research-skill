# 任务切换与研究材料交接

## 先确定交付物

每轮结合当前请求和已有项目背景，判断用户现在要修改、核验、登记还是解释。词语“证据”“保存”不是独立路由条件；也不因为上一轮在写作就继续使用写作流程。

| 当前交付物 | 主流程 | 完成依据 |
|---|---|---|
| 根据导师批注修改正文 | rw-phd-write | 对应批注、获准范围、替换稿及修改后复查；保留原稿不等于接受修订 |
| 为自己的研究项目保存修订来源、截图、材料状态 | rw-research-passport | 原始材料指针、稳定材料 ID、核验范围、审计记录和 validate 结果 |
| 保存作者已经确认的研究决定 | rw-research-passport | 可追溯的明确确认、Decision、Research Credential、适用范围与验证结果 |
| 仅保存普通对话恢复点或明确指定通用快照 | 宿主提供的通用保存功能；没有就说明没有 | 会话快照路径；不宣称登记了项目材料或决定 |
| 评审他人投稿稿件并归档评审意见 | 独立同行评审流程，如 rw-peer-review | 评审独立台账；不把评审结论放入作者项目的 Research Credential |
| 比较多项研究的支持、冲突和缺口 | rw-evidence-map | 研究与原文位置可追溯的证据关系；不把材料存盘等同证据综合 |
| 只询问“为什么用这个 Skill” | 当前路由判断 | 依据和纠正后的分工；问句本身不授权写入 |

本表是决策规则，不是按字符串匹配的程序。通用保存或同行评审模块未安装时说明真实缺口，不冒充执行，也不为登记自己的导师修订自动启动完整同行评审。

## 执行与告知

- 执行前简短说明本轮实际主 Skill 及其解决的问题。接续时说明接收者；只检查了某个入口就报告“已检查”，不报告已运行。
- 同一 Skill 的已读、未变规则可以复用，但本轮的输入定位、必要性判断和验收仍要实际进行。重复读取文件不等于完成审核。
- 按适用步骤验收，不为一个局部问题启动全部科研流程；解释性问题不强制产生文件。
- 保存任务获得授权后，在约定范围内完成原件留存、材料登记及验证。已存在副本时核对路径和内容，复用材料 ID，不重复制造档案。
- 路由被纠正后先核对当前请求：若原保存授权仍有效且用户未暂停或限定只讨论，就继续完成剩余步骤；若本轮只要求解释且没有有效保存授权，则只解释。两种情形都准确报告已完成、待完成和实际阻碍，不用“应该用某 Skill”代替已获准的执行。

## 署名、意见和作者决定

修订署名只证明该次修订记录的来源，不证明文本正确、是作者首次创作或已获作者接受。导师意见原文、助手解释和作者确认分别留存。发现署名后核对修改范围；保留或调整句子仍依据章节功能和证据，不因身份自动免审或推翻原判断。

用户要求“保存导师改动”时登记来源材料，不自动生成 confirmed 决定。只有作者明确采纳了具体安排，才按 Passport 生成对应决定凭据。原始评审意见和评审凭据留在独立台账；Passport 可以引用来源材料或台账的指针，不复制评审意见为项目决定。

## 完成条件

分别判断“原件已保存”“材料已登记”“决定已确认”“验证通过”。原件、登记、校验三样都核过，才能说“存好了”：原件核对路径和 hash，登记后回读到材料 ID，校验跑过 validate 并通过。少一样就说明做到哪一步、卡在哪。没有决定产生时标记该项不适用，不凑造 Credential。文件存在不是完整登记；validate 通过仅证明结构，内容来源和确认权限仍需对照原始材料。

交付只列当前任务需要的路径、材料 ID、验证结果及未完成项。整个过程不接受／拒绝 Word 修订，不解决批注，不改论文正文，除非用户另有明确授权。
